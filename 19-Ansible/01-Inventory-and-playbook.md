# Ansible: инвентарь и playbook

> **Уровень:** начальный · **Время:** 35–45 минут · **Предварительные знания:** Linux, SSH и YAML.

## Модель

Inventory описывает управляемые узлы и группы. Playbook описывает желаемую последовательность задач. Ansible подключается к узлам и применяет модули; цель — получить нужное состояние повторяемо.

## Минимальный локальный пример

Убедись, что Ansible установлен в учебной среде. Создай inventory:

~~~ini
[local]
localhost ansible_connection=local
~~~

Создай playbook:

~~~yaml
- name: Проверить локальный узел
  hosts: local
  gather_facts: false
  tasks:
    - name: Убедиться, что команда id выполняется
      ansible.builtin.command: id
      changed_when: false
~~~

Запусти проверку синтаксиса и выполнение:

~~~bash
ansible-playbook -i inventory.ini check.yml --syntax-check
ansible-playbook -i inventory.ini check.yml
~~~

Сохрани inventory.ini и check.yml в отдельном каталоге лаборатории. Команда id только читает сведения о текущем пользователе. changed_when: false сообщает Ansible, что эта проверочная команда не изменяет целевое состояние.

## Идемпотентность

Задача идемпотентна, если повторное применение при неизменившихся условиях не создаёт новых изменений. Модуль command сам по себе не гарантирует идемпотентность; для управления состоянием предпочитай специализированные модули, когда они доступны.

## Итог

Ansible описывает и применяет желаемое состояние, а безопасный playbook должен быть проверяемым, ограниченным по области действия и повторяемым.
