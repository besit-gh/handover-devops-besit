# Пользователи, группы и права доступа в Linux

> **Уровень:** начальный · **Время:** 40–55 минут · **Предварительные знания:** файловая система и навигация.

## Модель доступа

Linux проверяет доступ с учётом идентификатора пользователя, групп, прав объекта и дополнительных механизмов контроля. Для обычных файлов базовые права описывают чтение (r), запись (w) и выполнение (x) отдельно для владельца, группы и остальных пользователей.

## Посмотреть права

~~~bash
id
ls -l /etc/hosts
stat /etc/hosts
~~~

В выводе ls -l строка вроде -rw-r--r-- содержит тип объекта и права. Права — не единственный фактор: ACL, параметры монтирования, SELinux/AppArmor и другие ограничения тоже могут влиять на доступ.

## Практика в изолированном каталоге

~~~bash
mkdir -p ~/devops-lab/permissions
cd ~/devops-lab/permissions
printf '#!/bin/sh\necho hello\n' > hello.sh
ls -l hello.sh
chmod u+x hello.sh
./hello.sh
~~~

Это меняет права только у тестового файла в домашнем каталоге. chmod u+x добавляет право выполнения владельцу. Файл всё ещё может не запускаться из-за неверного интерпретатора, формата или параметров монтирования.

## Владелец и группа

~~~bash
id
stat hello.sh
~~~

Владелец и группа определяют, какие классы прав применяются. Не меняй владельца системных файлов ради эксперимента. chown и usermod требуют осторожности и часто административных прав.

## Диагностика Permission denied

1. Проверь точный путь и права каждого каталога в пути.
2. Проверь владельца и группы.
3. Проверь ACL и ограничения безопасности, если базовые права выглядят корректно.
4. Проверь, не смонтирована ли файловая система с ограничением выполнения.
5. После исправления повтори именно ту операцию, которая не работала.

Не используй chmod -R 777 как универсальное исправление: оно открывает лишний доступ и скрывает исходную причину.
