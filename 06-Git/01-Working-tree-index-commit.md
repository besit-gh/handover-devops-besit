# Рабочая директория, индекс и коммит

> **Уровень:** начальный · **Время:** 30–40 минут · **Предварительные знания:** терминал и файлы.

## Модель Git

Git различает рабочую директорию, индекс (staging area) и историю коммитов. Изменение файла не попадает в следующий коммит автоматически: его нужно добавить в индекс.

~~~text
Рабочая директория → Индекс → Коммит
   редактирование    git add   git commit
~~~

## Безопасная практика

~~~bash
mkdir -p ~/devops-lab/git-demo
cd ~/devops-lab/git-demo
git init
printf 'first version\n' > notes.txt
git status
git add notes.txt
git diff --cached
git commit -m "Add first note"
git log --oneline
~~~

Если Git сообщает, что имя или email не настроены, настрой их только после проверки желаемой идентичности:

~~~bash
git config user.name
git config user.email
~~~

Для локального учебного репозитория можно задать локальные значения командой git config user.name и git config user.email без флага --global.

## Проверка перед коммитом

- git status показывает, какие файлы изменены.
- git diff показывает изменения в рабочей директории, ещё не добавленные в индекс.
- git diff --cached показывает то, что попадёт в следующий коммит.
- git log --oneline показывает историю.

Не добавляй в Git файлы с паролями, токенами, приватными ключами или локальными состояниями инфраструктуры.

Индекс позволяет осознанно выбрать содержимое коммита и уменьшает риск случайно включить лишние изменения.
