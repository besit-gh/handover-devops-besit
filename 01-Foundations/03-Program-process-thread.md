# Программа, процесс и поток

> **Курс:** 01-Foundations · **Модуль:** Компьютер и ОС · **Уровень:** начальный · **Время:** 25–40 минут · **Среда:** Ubuntu в WSL2.

## Цели
Отличать программу, процесс и поток; находить PID/PPID; читать сведения о процессе; объяснять многопоточность; безопасно завершать тестовый процесс.

**Критерий прохождения:** правильно ответить на контрольные вопросы. Практика закрепляет знания.

## Модель
~~~text
Программа — файл или набор инструкций
      │ запуск
      ▼
Процесс — экземпляр выполнения со своим состоянием и ресурсами
      │ содержит
      ▼
Потоки — пути выполнения инструкций внутри процесса
~~~
Потоки одного процесса обычно разделяют адресное пространство и многие ресурсы, но имеют собственные стеки и состояние выполнения. Разные процессы обычно изолированы границами виртуальной памяти.

## Программа и процесс
~~~bash
/usr/bin/sleep 60
sleep 120 &
pgrep -a -x sleep
~~~
Файл программы может существовать без запущенного процесса. Символ & запускает команду в фоне. PID у тебя будет другим.

Подставь свой PID:
~~~bash
ps -o pid,ppid,stat,comm,args -p 1842
~~~
- PID — идентификатор процесса.
- PPID — идентификатор родителя.
- STAT — состояние.
- COMM — короткое имя.
- ARGS — командная строка.

S обычно означает прерываемый сон: процесс ждёт событие. Сам по себе этот статус не доказывает зависание. R — выполняется или готов к выполнению; D — непрерываемое ожидание; T — остановлен или трассируется; Z — завершился, но запись ещё ожидает обработки родителем.

## Сведения из /proc
~~~bash
cat /proc/1842/status
grep -E '^(Name|State|Pid|PPid|Threads):' /proc/1842/status
~~~
Пример вывода:
~~~text
Name:   sleep
State:  S (sleeping)
Pid:    1842
PPid:   1200
Threads:        1
~~~
Значения условные. /proc — виртуальная файловая система, через которую ядро предоставляет сведения о процессах.

## Несколько потоков
Этот пример создаёт тестовый процесс Python с тремя дополнительными потоками; он не устанавливает пакеты и не меняет системную конфигурацию.
~~~bash
python3 -c 'import threading,time; [threading.Thread(target=time.sleep,args=(60,),daemon=True).start() for _ in range(3)]; time.sleep(60)' &
pid=$!
sleep 1
ps -T -p "$pid" -o pid,spid,stat,comm
~~~
Ожидается несколько строк с одним PID и разными идентификаторами потоков. SPID в выводе Linux ps обозначает идентификатор потока (TID).
~~~bash
kill "$pid"
wait "$pid" 2>/dev/null || true
~~~

## Безопасное завершение
~~~bash
kill 1842
ps -p 1842
~~~
Если процесс завершился, ps не покажет его строку. Не начинай с kill -9: SIGKILL нельзя обработать для обычной очистки. Сначала выясни причину и используй наименее жёсткий подход.

## Диагностика: процесс есть, сервис недоступен
Причины: неправильный адрес или порт, недостаток прав, ожидание базы данных, заблокированные потоки или исчерпание ресурсов.
~~~bash
ps -p PID -o pid,ppid,stat,%cpu,%mem,etime,args
cat /proc/PID/status
ss -lntp
~~~
Замени PID числовым идентификатором. ss -lntp показывает слушающие TCP-сокеты; сведения о процессах могут быть ограничены правами пользователя. Собирай факты до изменения конфигурации или перезапуска.

## Шпаргалка
| Задача | Команда |
|---|---|
| Найти процесс | pgrep -a -x sleep |
| Параметры процесса | ps -p PID -o pid,ppid,stat,args |
| Сведения ядра | cat /proc/PID/status |
| Потоки | ps -T -p PID |
| Завершить процесс | kill PID |
| Слушающие TCP-порты | ss -lntp |

## Термины
- **PID:** идентификатор процесса.
- **PPID:** идентификатор родительского процесса.
- **TID:** идентификатор потока в Linux.
- **Планировщик:** механизм ядра, распределяющий процессорное время.
- **Виртуальная память:** адресное пространство процесса.
- **Конкурентность:** задачи продвигаются в работе в перекрывающиеся промежутки времени.
- **Параллелизм:** задачи фактически выполняются одновременно.

3. Чем поток отличается от процесса с точки зрения памяти и ресурсов?

5. Почему обычно сначала используют kill PID, а не kill -9 PID?
