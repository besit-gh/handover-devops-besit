# Переменные окружения и окружение процесса

> Начальный уровень · 30–40 минут · Требуются терминал и понятие процесса.

## Цель
Понять, как процесс получает настройки и почему переменная окружения не является универсальным хранилищем секретов.

## Исследование

~~~bash
printf 'HOME=%s\n' "$HOME"
env | sort | head -n 20
printenv PATH
~~~

Окружение — набор пар ключ-значение, передаваемый процессу при запуске. Дочерний процесс обычно наследует окружение родителя, но может получить изменённый набор переменных.

~~~bash
DEMO_MODE=training sh -c 'printf "%s\n" "$DEMO_MODE"'
printf 'После команды: %s\n' "${DEMO_MODE-unset}"
~~~

Первая команда задаёт переменную только для запуска одной команды.

## Практика
1. Найди PATH и объясни, как оболочка ищет исполняемые файлы.
2. Запусти дочерний shell с временной переменной.
3. Сравни NAME=value command и переменную, экспортированную через export.
4. Не выводи в общий лог реальные токены и пароли.

## Диагностика
- Приложение не видит переменную: проверь, передана ли она процессу и верно ли имя.
- Работает в терминале, но не как systemd unit: окружения оболочки и службы различаются.
- Секрет попал в лог: считай его раскрытым и следуй процессу отзыва/ротации.

2. Почему сервис может не видеть переменную из ~/.bashrc?
3. Почему env не следует бездумно публиковать в тикетах?
