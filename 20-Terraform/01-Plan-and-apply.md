# Terraform: планирование и применение

> **Уровень:** начальный · **Время:** 35–45 минут · **Предварительные знания:** Git, сети и основы облачной модели.

## Модель

Terraform сравнивает желаемую конфигурацию с известным состоянием и доступными данными провайдера, чтобы построить план изменений. Команда plan показывает предполагаемые действия; apply выполняет изменения. План может содержать создание, изменение или удаление ресурсов.

## Безопасный старт

Первые упражнения выполняй в локальной лаборатории или отдельном тестовом облачном аккаунте. Не запускай apply в чужом или production-окружении без проверки контекста и полномочий.

Простейший конфигурационный файл main.tf может содержать только блок terraform и провайдер, выбранный для лаборатории. До обращения к внешнему провайдеру проверь версию Terraform и документацию используемого провайдера.

## Рабочий цикл

~~~bash
terraform fmt -check
terraform init
terraform validate
terraform plan
~~~

- fmt проверяет форматирование.
- init подготавливает провайдеры и backend.
- validate проверяет синтаксис и внутреннюю согласованность конфигурации.
- plan показывает предполагаемые изменения.

Apply выполняй только после чтения плана и подтверждения, что аккаунт, регион, workspace и набор изменений ожидаемы.

## Риски state

State может содержать чувствительные значения и сведения об инфраструктуре. Не коммить state-файлы в Git. Для командной работы обычно требуется защищённый remote backend с блокировкой и контролем доступа.
