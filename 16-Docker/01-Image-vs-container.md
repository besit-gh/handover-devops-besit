# Образ и контейнер Docker

> **Уровень:** начальный · **Время:** 35–45 минут · **Предварительные знания:** Linux, процессы и файловая система.

## Модель

Образ — версионируемый шаблон файловой системы и метаданных для запуска приложения. Контейнер — экземпляр образа с собственным состоянием выполнения и изолированными ресурсами. Один образ может использоваться для запуска нескольких контейнеров.

## Исследование

Если Docker установлен и демон доступен:

~~~bash
docker version
docker image ls
docker ps -a
~~~

Первая команда показывает сведения о клиенте и сервере Docker. Если клиент не может связаться с демоном, это ещё не проблема приложения: сначала нужно проверить состояние Docker Engine и доступ к нему.

## Запуск тестового контейнера

~~~bash
docker run --rm hello-world
~~~

Docker при необходимости загрузит образ, создаст контейнер, выполнит программу и удалит контейнер после завершения благодаря --rm. Образ обычно останется локально.

## Посмотреть слои и состояние

~~~bash
docker image inspect hello-world
docker ps -a
~~~

Образ и контейнер — разные объекты. Удаление контейнера не обязательно удаляет образ; удаление образа не должно рассматриваться как способ остановить работающий сервис.

## Важные границы

Контейнеры используют ядро хостовой ОС. Изоляция процессов и файловой системы не означает, что контейнер автоматически безопасен: важны права пользователя, capabilities, mounts, сеть, секреты и лимиты ресурсов.

## Итог

Образ описывает то, из чего запускают приложение; контейнер — конкретный экземпляр выполнения.
