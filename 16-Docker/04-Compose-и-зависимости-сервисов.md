# Docker Compose: зависимости, health check и локальная среда

## Результат
Поднимать несколько связанных сервисов воспроизводимо, отличать запуск контейнера от готовности приложения и безопасно останавливать учебное окружение.

## Зависимости
[Образы и контейнеры](./01-Image-vs-container.md), [Тома и сеть контейнеров](./02-Volumes-and-container-networking.md), [Dockerfile и контекст сборки](./03-Dockerfile-and-build-context.md).

## 1. Compose описывает желаемую локальную систему
Файл Compose фиксирует сервисы, сборку, сети, тома, переменные и проверки. Он помогает команде повторить одинаковое окружение, но не заменяет production-план высокой доступности, backup или управления секретами.

```yaml
services:
  web:
    build: .
    ports:
      - "127.0.0.1:8080:8080"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8080/health', timeout=2).read()"]
      interval: 10s
      timeout: 3s
      retries: 3
```

Порт привязан к loopback, чтобы не публиковать учебный сервис в локальную сеть без необходимости.

## 2. Запуск не означает готовность
Контейнер может находиться в состоянии running, но приложение ещё не слушает порт, не закончило миграции или не может подключиться к зависимости. Health check должен проверять реальный контракт сервиса. Не используйте только проверку существования процесса как доказательство готовности HTTP API.

`depends_on` задаёт порядок старта, но сам по себе не гарантирует, что зависимость уже готова принимать запросы. При поддержке Compose можно использовать условие healthcheck; приложение всё равно должно корректно переживать временную недоступность зависимостей.

## 3. Повторяемые команды
```bash
docker compose config
docker compose up --build -d
docker compose ps
docker compose logs --tail 100
docker compose down
```

Перед запуском проверяйте итоговую конфигурацию. Команда config может показать подставленные значения переменных; не публикуйте вывод, пока не убедились, что там нет секретов.

## 4. Лаборатория
Используйте [демонстрационный сервис](../90-Capstone-Projects/demo-servicio/README.md). Поднимите его через Compose, проверьте /health, затем измените health check на неправильный порт и наблюдайте, чем отличается состояние контейнера от состояния приложения. Верните конфигурацию и подтвердите восстановление.

## Ошибки
- Публиковать все порты на 0.0.0.0 без необходимости.
- Хранить реальные credentials в compose.yaml.
- Путать depends_on с проверкой готовности.
- Удалять volumes, не выяснив, хранят ли они нужные данные.
- Не проверять итоговую конфигурацию перед запуском.
