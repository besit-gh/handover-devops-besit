# Лаборатория: Permission denied в Linux

> Начальный уровень · 25–40 минут · Только отдельный каталог домашней директории.

## Цель
Найти причину отказа доступа без массового ослабления прав.

## Подготовка

~~~bash
mkdir -p ~/devops-lab/permission-incident
cd ~/devops-lab/permission-incident
printf '#!/bin/sh\necho lab-ok\n' > run.sh
chmod 600 run.sh
./run.sh
~~~

Последняя команда должна завершиться отказом: у файла нет права выполнения для текущего пользователя.

## Задание
Не исправляй проблему сразу. Собери факты через ls -l, stat и id. Затем добавь право выполнения только владельцу и проверь повторно.

~~~bash
chmod u+x run.sh
./run.sh
~~~

Ожидаемый результат — lab-ok. Не используй chmod 777.

## Проверка понимания
1. Какая проверка доступа не прошла?
2. Почему chmod u+x лучше, чем chmod 777?
3. Как изменится анализ, если нет права прохода по родительскому каталогу?
