# Лаборатория: неудачный релиз контейнерного сервиса

## Цель и безопасность
Отработать диагностику релиза, который развернулся, но не проходит health check. Только локальная учебная среда; заранее сохраните рабочий образ. Не используйте production-ресурсы или реальные credentials.

## Сценарий
После выпуска endpoint не отвечает или health check провален. Причина может быть в процессе, порте, конфигурации, сети или endpoint. Не делайте вывод по одному неудачному запросу.

## Шаг 1. Зафиксируйте симптомы
Запишите время, commit, image tag/digest, точный URL, HTTP-статус и влияние на пользователя.

## Шаг 2. Идите от процесса к запросу
```bash
docker ps -a
docker inspect <container-name>
docker logs --tail 100 <container-name>
docker port <container-name>
curl -v --max-time 3 http://127.0.0.1:<published-port>/health
```
Замените placeholders реальными значениями. Перед передачей вывода inspect проверьте, нет ли в нём environment variables или чувствительных параметров.

Проверьте последовательно:
1. контейнер существует и не завершился;
2. процесс не падает при старте;
3. приложение слушает ожидаемый внутренний порт;
4. порт опубликован на нужном интерфейсе;
5. endpoint существует и возвращает ожидаемый статус;
6. health check использует правильный адрес и порт.

## Шаг 3. Проверяемая гипотеза
Пример: приложение слушает 8080, а health check обращается к 8081. Измените только предполагаемую причину и повторите тот же тест. Сохраните исходный результат для сравнения.

## Шаг 4. Восстановление
Если исправление не подтверждено, вернитесь к известному рабочему образу. Не перезаписывайте старый тег новым образом; используйте разные идентификаторы. После rollback повторите исходный запрос и базовый пользовательский сценарий.

Откат приложения не возвращает автоматически миграции БД, внешние сообщения и изменённые данные. Если релиз менял состояние, следуйте отдельному плану восстановления.

## Критерии завершения
- причина подтверждена фактом, а не догадкой;
- восстановление подтверждено исходной проверкой;
- сохранены commit и image идентификаторы;
- описаны влияние, остаточные риски и мера предотвращения повтора.
