# Первый безопасный Bash-скрипт

> **Уровень:** начальный · **Время:** 30–45 минут · **Предварительные знания:** терминал, пути и коды завершения.

## Цель

Создать простой скрипт, который проверяет входные данные, сообщает результат и возвращает понятный код завершения.

## Скрипт

Создай файл check-path.sh:

~~~bash
#!/usr/bin/env bash
set -u

if [ "$#" -ne 1 ]; then
  printf 'Использование: %s ПУТЬ\n' "$0" >&2
  exit 2
fi

path=$1

if [ -e "$path" ]; then
  printf 'Путь существует: %s\n' "$path"
  exit 0
else
  printf 'Путь не найден: %s\n' "$path" >&2
  exit 1
fi
~~~

Сделай файл исполняемым и запусти его на тестовом пути:

~~~bash
chmod u+x check-path.sh
./check-path.sh "$HOME"
./check-path.sh "$HOME/this-path-should-not-exist"
echo "$?"
~~~

## Разбор

- Shebang указывает интерпретатор.
- "$#" — количество аргументов.
- "$1" — первый аргумент; кавычки защищают путь с пробелами.
- >&2 направляет диагностическое сообщение в stderr.
- exit 0 означает успешную проверку; exit 1 — путь не найден; exit 2 — неправильный вызов.

Скрипт намеренно только проверяет путь. Он ничего не удаляет и не меняет системную конфигурацию.

## Надёжность

Не полагайся на set -e как на универсальную обработку ошибок: его поведение зависит от контекста команд. Проверяй критические результаты явно и проектируй понятные коды завершения.

## Контрольные вопросы

1. Почему "$1" заключён в кавычки?
2. Почему сообщение об ошибке направляется в stderr?
3. Чем коды 1 и 2 различаются в этом скрипте?
4. Что изменится, если путь содержит пробелы?

## Итог

Надёжный shell-скрипт проверяет входные данные, выдаёт диагностические сообщения и использует коды завершения осмысленно.
