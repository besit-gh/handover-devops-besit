# Bash: pipelines, `pipefail` и гарантированная очистка

## Результат обучения

После урока вы сможете объяснить, почему успешный статус pipeline не всегда означает успех всех команд, корректно использовать `PIPESTATUS`, `pipefail` и `trap`, а также не терять исходную ошибку при очистке временных ресурсов.

## 1. Что возвращает pipeline

В Bash команда `producer | filter | consumer` по умолчанию получает код завершения **последней** команды. Например, если `grep` не нашёл совпадений, он вернёт 1, но если следующий `sort` завершился успешно, весь pipeline без дополнительных настроек может вернуть 0.

```bash
false | true
printf 'status=%s\n' "$?"
```

В обычном Bash этот пример печатает `status=0`. Для диагностики всех компонентов сразу используйте массив `PIPESTATUS` — считывайте его немедленно, потому что следующая команда перезапишет значения:

```bash
false | true
statuses=( "${PIPESTATUS[@]}" )
printf 'first=%s second=%s\n' "${statuses[0]}" "${statuses[1]}"
```

Включённая опция `set -o pipefail` делает код pipeline ненулевым, если ненулевой код вернула хотя бы одна команда. При этом итоговый код соответствует крайней справа команде, завершившейся с ошибкой.

## 2. Не превращайте `set -e` в магию

`set -e` завершает shell при некоторых ошибках, но у него есть контекстные исключения: например, проверки в `if`, части логических выражений и некоторые pipeline. Не используйте его как замену осмысленной обработке ошибок. Для скриптов с pipeline часто уместно:

```bash
set -o nounset
set -o pipefail
```

Добавляйте `errexit` только если понимаете поведение всех команд и мест, где ожидается ненулевой статус.

## 3. Очистка через trap

Временные файлы следует создавать предсказуемо и удалять при штатном завершении или сигнале:

```bash
#!/usr/bin/env bash
set -o nounset
set -o pipefail

tmpdir=$(mktemp -d)
cleanup() {
  local rc=$?
  trap - EXIT
  rm -rf -- "$tmpdir"
  exit "$rc"
}
trap cleanup EXIT

printf 'temporary data\n' > "$tmpdir/input.txt"
grep -q 'temporary' "$tmpdir/input.txt"
```

`mktemp -d` создаёт каталог с уникальным именем. `rm -rf -- "$tmpdir"` безопасен только потому, что переменная получена непосредственно из `mktemp`, а не из произвольного пользовательского ввода. Никогда не подставляйте непроверенную строку в разрушительную команду.

Сохранение `rc=$?` до команд очистки важно: сама очистка может изменить `$?`. В этом шаблоне `trap - EXIT` предотвращает повторный вызов обработчика при его собственном `exit`.

## 4. Практика в отдельном временном каталоге

```bash
tmpdir=$(mktemp -d)
printf 'alpha\nbeta\n' > "$tmpdir/data"
grep 'missing' "$tmpdir/data" | sort
echo "pipeline status=$?"
set -o pipefail
grep 'missing' "$tmpdir/data" | sort
echo "pipeline status with pipefail=$?"
rm -rf -- "$tmpdir"
```

Ожидаемая идея: первый pipeline может выглядеть успешным из-за `sort`; второй должен отражать отсутствие совпадений. Не используйте `grep` без совпадения как автоматическое доказательство сбоя системы: статус 1 означает «совпадений нет», а не обязательно ошибку выполнения.

## 5. Типичные ловушки

- Чтение `$?` после команды логирования вместо исходной команды.
- Чтение `PIPESTATUS` после `echo`, когда массив уже изменился.
- Предположение, что `set -e` гарантирует остановку при любой ошибке.
- Использование `trap` для удаления каталога, путь к которому получен от пользователя.
- Маскировка ошибки основного действия успешной очисткой.
