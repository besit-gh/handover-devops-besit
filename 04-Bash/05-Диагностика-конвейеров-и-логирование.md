# Bash: диагностика конвейеров и журналирование

## Что освоить
Научиться строить конвейер так, чтобы сбои не терялись, а диагностика оставляла полезный контекст без утечки секретов.

## Зависимости
Уроки [Коды завершения и обработка ошибок](./02-Exit-codes-and-safe-error-handling.md) и [Конвейеры, trap и pipefail](./04-Pipelines-traps-and-pipefail.md).

## 1. Разделяйте данные и диагностику
В Unix-процессах стандартный вывод (stdout) предназначен для результата, а стандартный поток ошибок (stderr) — для сообщений о ходе работы и проблемах. Это позволяет передавать данные следующей команде, не засоряя их текстом логов.

```bash
printf 'обрабатываю файл: %s\n' "$file" >&2
process_file "$file"
```

Не выводите в лог токены, пароли, содержимое приватных ключей и целиком environment. Лог должен объяснять событие, а не раскрывать секреты.

## 2. Сохраняйте статус pipeline
При включённом `pipefail` ошибка раннего этапа не скрывается успешным последним этапом. Если нужно понять конкретную команду, скопируйте `PIPESTATUS` немедленно после pipeline:

```bash
producer | transformer | consumer
codes=( "${PIPESTATUS[@]}" )
printf 'producer=%s transformer=%s consumer=%s\n' "${codes[0]}" "${codes[1]}" "${codes[2]}" >&2
```

После следующей команды значения `PIPESTATUS` уже могут быть другими.

## 3. Добавляйте контекст, а не шум
Полезное сообщение отвечает на вопросы: какая операция выполнялась, над каким безопасным идентификатором, что ожидалось и что пошло не так. Для длительных задач фиксируйте начало, завершение и длительность. Не выводите каждую строку огромного входного файла в лог.

## 4. Практика
Создайте скрипт, который читает список файлов, проверяет существование каждого и собирает отчёт. Результат направляйте в stdout, диагностику — в stderr. Намеренно укажите отсутствующий файл и убедитесь, что скрипт возвращает ненулевой статус, но продолжает обработку остальных файлов по заданной политике.

## Ошибки
- Использовать `2>&1` без понимания, куда попадёт поток.
- Считать, что логирование само по себе сохраняет exit code.
- Игнорировать ошибку producer, потому что consumer завершился с кодом 0.
- Логировать полный ввод и случайно раскрывать секреты.
- Писать «ошибка» без операции, причины и следующего действия.
