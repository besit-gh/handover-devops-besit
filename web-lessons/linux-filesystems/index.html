01 / Осмотреть

Что система видит?

Не путай физическое устройство, раздел, файловую систему и каталог, куда она подключена. Начинай с наблюдения, а не с форматирования.

lsblk -f

Дерево устройств, тип ФС, метка, UUID и точки монтирования.

blkid

Идентификаторы и тип файловой системы на блочных устройствах.

findmnt

Что и куда смонтировано прямо сейчас.

df -hT

Использование места по смонтированным файловым системам.

Выбери устройство в виртуальной схеме

Вывод/dev/sda2
NAME   FSTYPE UUID                                 MOUNTPOINTS
sda
└─sda2 ext4   1111-ROOT                             /

Корневая файловая система смонтирована в /.

Безопасный порядок: сначала lsblk -f, затем сверить UUID/тип/назначение, потом решить, что делать. mkfs создаёт новую файловую систему и может уничтожить прежние данные — не используй его как диагностическую команду.
02 / Подключить

Монтирование — это не форматирование

Монтирование делает дерево файлов выбранной файловой системы доступным из каталога. Содержимое каталога назначения скрывается на время монтирования; оно не удаляется автоматически.

Вручную
sudo mkdir -p /srv/data
sudo mount /dev/sdb1 /srv/data
findmnt /srv/data
Отключить
sudo umount /srv/data
findmnt /srv/data

Если занято — выясни, кто держит файлы: не начинай с принудительного отключения.

Лаборатория: подключи диск

Это изолированная симуляция. Команды не запускаются на настоящем компьютере.

root@lab:~виртуальная среда
Lab ready. Подсказка: lsblk -f
$
Важно: в реальной системе перед umount проверь рабочий каталог, открытые файлы и потребителей mountpoint. Нельзя считать, что отключение безопасно только потому, что команда существует.
03 / Автоматизировать

/etc/fstab: конфигурация, которая переживает перезагрузку

Запись содержит источник, точку монтирования, тип ФС, параметры, dump и fsck pass. Для постоянных данных обычно надёжнее указывать UUID, а не имя вроде /dev/sdb1, которое может измениться.

ПолеПримерСмысл
ИсточникUUID=abcd-1234Идентификатор ФС
Точка/srv/dataКаталог подключения
Типext4Драйвер/формат ФС
ПараметрыdefaultsРежим монтирования
dump / pass0 2Поля резервного копирования и проверки при загрузке; зависят от ФС/дистрибутива

Найди ошибку в записи

Ниже конфигурация содержит ошибку. Выбери правильную запись, затем проверь её кнопкой «Проверить конфигурацию».

UUID=1111-ROOT  /          ext4  defaults  0 1
UUID=abcd-1234  /srv/data  ext4  defaults  0 2
UUID=beef-9999  /mnt/backup xfs   defaults  0 0
Проверка конфигурации — это не магия: источник должен существовать, тип совпадать, а точка монтирования быть подготовлена.
Перед перезагрузкой: резервная копия файла → проверка UUID через blkid → sudo findmnt --verify --verbose (поддержка зависит от версии util-linux) → sudo mount -a → проверка findmnt и журналов. На удалённом сервере заранее продумай доступ к консоли и откат. nofail может помочь при необязательном диске, но не исправляет неверный UUID.
04 / Отличить симптомы

Место закончилось? Или что-то другое?

Блоки

Файловая система заполнена данными.

df -hT
Inode

Много мелких файлов исчерпали записи.

df -i
Каталог

Найти, что занимает место.

du -xhd1 /var

Если df показывает занятое место, а du не находит больших каталогов, проверь удалённые, но всё ещё открытые файлы: sudo lsof +L1 (если установлен). Не удаляй наугад файлы журналов и не запускай fsck на смонтированной ФС.

Симулятор диагностики

Выбери симптом. Цель — собрать следующую полезную улику, а не немедленно «починить» систему.

Выбери симптом и получи план диагностики.
Продвинутый уровень: read-only, fsck и SMART
  • findmnt -no SOURCE,FSTYPE,OPTIONS /srv/data помогает увидеть источник, тип и параметры.
  • dmesg -T или journalctl -k — сообщения ядра о I/O и файловой системе.
  • fsck применяют к подходящей размонтированной файловой системе; сначала оценить резервные копии и причину сбоя.
  • SMART доступен не для всех устройств/контроллеров; используйте smartctl, если установлен, и не путайте предупреждения с гарантированным диагнозом.
  • Для критичных данных — снимок/резервная копия до разрушительных операций.
05 / Production-сценарий

Инцидент: приложение не видит данные

После перезапуска сервера приложение пишет «каталог пуст». Диск не исчез. Твоя задача — понять, что именно произошло, и доказать исправление.

Симптом

Сервис стартовал, но /srv/data пустой. На диске есть данные, а приложение ожидает каталог с отчётами.

Ограничения

Не форматировать. Не удалять данные. Не перезагружать повторно без причины. Сначала собрать состояние.

Шаг 1. Выбери наиболее полезную первую команду

Выбери действие. Важнее всего сейчас — отличить отсутствие mount от повреждения данных.

Шаг 2. Улика

lsblk -f:
sdb1 ext4 UUID=abcd-1234
findmnt /srv/data:
(пусто)
cat /etc/fstab:
UUID=abcd-1234 /srv/data ext4 defaults 0 2

Точка назначения существует, но источник не смонтирован. Безопасная следующая последовательность — проверить запись, выполнить тестовое монтирование и подтвердить результат.

Критерий завершения: ты можешь показать, какой источник смонтирован в каталог, подтвердить UUID и тип ФС, проверить запись fstab, а при симптоме «нет места» различить блоки и inode.

Лаборатория учебная. Терминал моделирует небольшой набор команд и не выполняет команды на твоём устройстве. Для реальных операций сверяйся с документацией своего дистрибутива и сначала проверяй состояние.
