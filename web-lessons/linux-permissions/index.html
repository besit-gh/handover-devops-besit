01 · Маршрут

Что ты должен уметь после урока

Понимать

  • как Linux выбирает класс прав: владелец, группа, остальные;
  • почему x у каталога — не то же самое, что у файла;
  • как работают специальные биты, ACL и umask.

Делать

  • читать ls -l и stat;
  • переводить rwxr-x--- в 750 и обратно;

Правило безопасности: все команды в симуляторе — только текстовые примеры. Для реальной практики используй отдельный каталог в своей лабораторной среде.

02 · Базовая модель

Три права × три класса

Для обычного файла и каталога существуют три базовых права. Они проверяются относительно идентификаторов процесса: эффективного UID/GID и дополнительных групп. Для обычных локальных файловых систем класс прав выбирается по правилам ядра, а не по принципу «сложить все подходящие права».

r

Read · чтение

Файл: прочитать содержимое. Каталог: получить список имён (обычно вместе с правом прохода).

w

Write · запись

Файл: изменить содержимое. Каталог: создавать, удалять и переименовывать записи — обычно при наличии x.

x

Execute · выполнение

Файл: выполнить как программу, если это допускают формат, mount options и другие проверки. Каталог: искать имена и проходить по пути.

Интерактивная матрица прав

Нажимай биты — строка режима и восьмеричное значение обновятся автоматически.

Символьная запись
rwxr-x---

Первые три бита — владелец, следующие — группа, последние — остальные.

Восьмеричная запись
750

r = 4, w = 2, x = 1. Складывай значения внутри каждой тройки.

Запомни: chmod 640 report.txt задаёт владельцу rw-, группе r--, остальным ---. Это не означает, что root и дополнительные механизмы доступа игнорируются.
03 · Инструмент

Калькулятор chmod

Проверяй оба направления преобразования. Символьные режимы применяются к существующим правам, поэтому u+x и u=rw — разные операции.

Восьмеричный режим → права

Введи три цифры (например, 754) или четыре, если нужен специальный бит (например, 4755).

Символьный режим → пояснение

Поддерживаются учебные выражения вида chmod u+x file, chmod g-w file, chmod a=r file и числовые режимы. Это объяснитель, а не оболочка.

Три способа думать о режиме

Осторожно с 777. Это не универсальное исправление. Оно может раскрыть чтение, изменение или запуск для всех локальных пользователей, а на общем каталоге — и возможность подменить файлы. Сначала выясни субъект, путь, ACL и требуемую минимальную привилегию.
04 · Семантика

Файл и каталог — разные модели

Обычный файл

БитПрактический смысл
rПрочитать содержимое файла
wИзменить содержимое (если прочие проверки разрешают)
xЗапросить выполнение файла

Каталог

БитПрактический смысл
rПеречислять имена записей
wМенять записи в каталоге; для типичных операций нужен ещё x
xПроходить по пути и искать известное имя
Контринтуитивный случай: право удалить файл в обычном каталоге зависит прежде всего от прав на каталог-родитель, а не от бита записи самого файла. Sticky bit может дополнительно ограничить удаление.

Проверка цепочки пути

Для доступа к /srv/app/config/secrets.env процесс должен пройти через каждый компонент пути. Недостаток права поиска x у любого родительского каталога может привести к отказу, даже если сам файл имеет 644.

id
namei -l /srv/app/config/secrets.env
stat /srv/app/config/secrets.env
getfacl /srv/app/config/secrets.env
05 · Блок-схема

Как диагностировать Permission denied

Не начинай с изменения прав. Сначала собери факты: кто выполняет действие, к какому объекту обращается, по какому пути и каким способом.

Важно: SELinux/AppArmor, read-only mount, immutable-атрибут, NFS root squash, ACL или права родительского каталога могут объяснять отказ, который не решается обычным chmod.
06 · Особые режимы

SUID, SGID и sticky bit

У режима файла есть дополнительные биты помимо девяти базовых. В числовой записи они стоят слева: например, 4755, 2750, 1777. Реальное поведение зависит от типа объекта, файловой системы и системных ограничений.

4xxx

SUID

Для исполняемого файла обычно задаёт effective UID владельца на время выполнения. Может быть проигнорирован на некоторых файловых системах и не работает как обычный механизм для скриптов на Linux.

chmod u+s program
ls -l program
2xxx

SGID

Для исполняемого файла влияет на effective GID; для каталога обычно обеспечивает наследование группы создаваемыми объектами (с нюансами реализации и umask).

chmod g+s shared/
ls -ld shared/
1xxx

Sticky bit

На общем каталоге ограничивает удаление и переименование записей: обычно действовать могут владелец файла, владелец каталога или привилегированный процесс.

chmod +t /tmp/example
ls -ld /tmp/example

Проверяй не только отображение s/t в ls -l, но и тип файла, владельца, контекст запуска и фактические ограничения системы.

07 · Дополнительные механизмы

ACL и umask: почему результат не всегда очевиден

ACL — права для конкретных субъектов

Access Control Lists позволяют задать права отдельному пользователю или группе сверх классической тройки. Маска ACL ограничивает эффективные права именованных записей и группы.

getfacl report.txt
setfacl -m u:alice:r-- report.txt
getfacl report.txt
setfacl -x u:alice report.txt

Перед изменением ACL сохрани текущее состояние. Не все файловые системы и окружения одинаково поддерживают ACL.

umask — маска новых объектов

umask вычитает запрещённые биты из режима, который запросило приложение при создании файла или каталога. Обычно базовые режимы — 666 для файла и 777 для каталога.

umask
umask 027
# типичные новые права:
# файл:    640
# каталог: 750

Это иллюстрация для приложений, которые запрашивают стандартные режимы; приложение может задать другой режим. umask не меняет права уже существующих объектов.

Мини-симулятор umask

Порядок диагностики: ls -l показывает обычный режим, но для полного объяснения проверь getfacl, владельца/группу, путь, mount options и механизм безопасности дистрибутива.
08 · Симулятор

Виртуальный терминал

Терминал ниже распознаёт ограниченный набор команд и показывает заранее подготовленные учебные результаты. Он не запускает shell, не читает файлы и не меняет твою систему. Используй команды как тренировку интерпретации вывода.

sandbox@linux-permissions:~
Учебная среда готова. Введи help, чтобы увидеть команды.
$
Не вставляй в этот симулятор секреты, реальные команды или команды для production. Здесь поддерживаются только учебные шаблоны: help, id, pwd, ls -l, stat, namei -l, getfacl, chmod (объяснение), clear.
