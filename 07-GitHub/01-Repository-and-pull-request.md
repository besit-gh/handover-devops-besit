# Репозиторий и pull request в GitHub

> Начальный уровень · 30–40 минут · Требуются Git и remote.

## Модель
Git хранит историю изменений, GitHub добавляет совместную работу: обсуждения, pull request, проверки и управление доступом. Pull request — предложение внести изменения из одной ветки в другую; это место для проверки diff, обсуждения рисков и подтверждения результата.

## Рабочий цикл
1. Создать отдельную ветку.
2. Сделать небольшие осмысленные коммиты.
3. Отправить ветку в remote.
4. Открыть pull request и описать цель, риски и способ проверки.
5. Разобрать review и результаты автоматических проверок.
6. Слить изменения по правилам проекта.

## Проверка перед слиянием
- Diff содержит только ожидаемые изменения.
- Секреты и локальные файлы не попали в коммиты.
- Проверки прошли на актуальном commit.
- Описание объясняет мотивацию и способ проверки.
- Для рискованных изменений предусмотрен откат.

1. Чем pull request отличается от коммита?
2. Почему review полезен даже для небольшого изменения?
3. Что проверить, если CI прошёл на старом commit?
