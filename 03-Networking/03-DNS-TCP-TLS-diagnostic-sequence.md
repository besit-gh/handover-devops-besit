# Диагностика пути: DNS → TCP → TLS → HTTP

> Средний уровень · 40–50 минут · Требуются базовые DNS, TCP, HTTP и TLS.

Не проверяй все уровни одной командой и не делай вывод о системе по одному успешному тесту. Последовательно разделяй разрешение имени, соединение с портом, TLS и прикладной ответ.

~~~bash
getent hosts example.com
ip route
curl -v --connect-timeout 3 --max-time 8 https://example.com/
~~~

- DNS не разрешает имя: исследуй системный резолвер, записи и кеш.
- TCP не устанавливается: проверь маршрут, listener и фильтрацию.
- TCP есть, TLS не проходит: проверь SNI, сертификат, время системы и доверенную цепочку.
- HTTP отвечает 4xx/5xx: переходи к заголовкам, телу ответа и серверным логам.

Не отключай проверку сертификатов ради проверки доступности: это может скрыть реальную проблему доверия.
