# Python: структурированные логи и коды завершения

## Результат
Сделать CLI-инструмент удобным для автоматизации: успешный результат отделён от диагностики, ошибки имеют понятный exit code, а записи логов можно фильтровать и анализировать.

## Зависимости
[CLI, файлы и ошибки](./01-CLI-files-and-errors.md) и [HTTP-клиент, таймауты и JSON](./02-HTTP-client-timeouts-and-json.md).

## 1. Контракт CLI
Утилита должна заранее определять:
- что выводится в stdout при успехе;
- какие сообщения идут в stderr;
- какие коды означают успех, некорректный ввод и операционную ошибку;
- какие ошибки допустимы и как их отличить;
- можно ли безопасно повторить команду.

Код 0 обычно означает успех. Ненулевые коды не следует выбирать случайно: документируйте значения и не меняйте их без причины, потому что их могут проверять другие скрипты.

## 2. Используйте модуль logging
Минимальная настройка:

```python
import logging
import sys

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
    stream=sys.stderr,
)
log = logging.getLogger("inventory-check")
```

Пишите сообщения с контекстом:

```python
log.info("Начата проверка", extra={"target_count": len(targets)})
```

Стандартный formatter не сериализует произвольные extra-поля автоматически. Если нужен машинно-читаемый JSON, используйте отдельный formatter и проверяйте его тестами. Не называйте обычный текстовый лог «JSON-логом».

## 3. Ошибки и exit code
Поймайте только те исключения, которые можете обработать осмысленно. Для ожидаемой ошибки ввода напечатайте краткое объяснение и завершитесь ненулевым кодом. Не перехватывайте все исключения и не продолжайте как будто операция прошла успешно.

```python
def main() -> int:
    try:
        run_check()
    except ValueError as exc:
        log.error("Некорректный ввод: %s", exc)
        return 2
    except OSError:
        log.exception("Операция с файловой системой не выполнена")
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Не включайте в сообщение секретные значения или целиком пользовательский документ. Для повторяющихся операций полезно добавить безопасный идентификатор задачи.

## 4. Практика и тестирование
Напишите функцию, которая возвращает результат и отдельный код завершения. Проверьте тестами успешный случай, некорректный аргумент и недоступный файл. Убедитесь, что тесты проверяют и stdout/stderr, если это часть контракта.

## Типичные ошибки
- Выводить диагностические сообщения в stdout и ломать JSON-пайплайн.
- Использовать один и тот же код для всех типов ошибки без документации.
- Записывать stack trace для каждой ожидаемой ошибки ввода.
- Проглатывать исключение и возвращать 0.
- Считать, что текстовый лог автоматически структурирован.
