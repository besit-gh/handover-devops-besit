# Тестирование CLI-инструмента

> Начальный → средний уровень · 35–45 минут · Требуются Git, shell и основы тестирования.

## Цель
Проверить CLI не только на успешном вводе, но и на граничных случаях и ошибках.

## Матрица сценариев
Для команды, принимающей путь к файлу, проверь:
- существующий обычный файл;
- пустой файл;
- путь с пробелом;
- отсутствующий путь;
- каталог вместо файла;
- отсутствие прав чтения;
- неверное число аргументов.

Для каждого сценария заранее запиши ожидаемые stdout, stderr и exit code. Код завершения важен для shell и CI не меньше текста сообщения.

## Изоляция тестов
Создавай временные файлы и очищай только их в teardown. Не используй реальные системные файлы. Тесты должны быть повторяемыми и не зависеть от порядка запуска.

## Практика
Выбери скрипт из курса Bash или Python. Реализуй три теста: успешный случай, некорректный ввод и отсутствующий файл. Объясни, какой класс дефектов обнаруживает каждый тест.

## Контрольные вопросы
1. Почему нужно проверять exit code, а не только stdout?
2. Что такое граничный случай?
3. Почему тесты не должны зависеть от данных на основной машине?
